# 唐代侠义诗第二轮系年设计

## 目标

在不把推测年份伪装成确切年份的前提下，修正现有日期审计中的状态混淆，并对最有可能通过年谱、编年全集和历史行迹获得结果的高频诗人作品开展第二轮人工系年。

本轮成功标准：

- “接口是否成功”与“作品是否可以系年”成为两个独立维度。
- 每个非空年代都有可追溯来源、证据说明、推断方法和复核状态。
- 单年、区间、争议年份、创作阶段和未知可以被可视化代码明确区分。
- 第一批优先核查 11 位高频诗人的 25 首未系年独立作品。
- 无充分证据的作品继续留空，不用作者生卒年或朝代中点补值。

## 范围

### 本轮包含

1. 扩展 `data/poem_dates.csv` 的状态与证据字段。
2. 修改 `scripts/build_poem_dates.py`，使重新运行开放接口时不会覆盖人工核查结果。
3. 增加测试，覆盖接口空响应、作品未收录、已匹配但无系年和人工证据合并。
4. 建立人工系年侧车数据文件，保存人工研究结果。
5. 首批核查王维、高适、卢照邻、李益、李白、李颀、王昌龄、杨炯、李峤、骆宾王、马戴共 25 首作品。
6. 更新 README，说明字段、证据层级、生成方式与局限。

### 本轮不包含

- 为全部 61 首未系年独立唐诗强行给出年代。
- 用作者生卒年直接代替作品写作时间。
- 修改现有网页的视觉编码或新增时间轴页面。
- 将低质量转载、无出处网页或搜索摘要作为最终年代依据。

## 方案选择

### 方案 A：只改状态标签

成本最低，但不能提高作品级系年覆盖率，也无法形成后续研究资产。

### 方案 B：状态修正加分批人工系年（采用）

先解决数据语义问题，再集中核查拥有年谱和编年整理成果的高频诗人。可以较快提高覆盖率，同时保留完整证据链。

### 方案 C：一次性核查全部未系年作品

覆盖面最大，但小诗人和乐府旧题常缺少可靠材料，容易在进度压力下产生低把握推断。本轮不采用。

## 数据架构

### 自动查询状态

新增 `lookup_status`：

- `matched`：开放接口匹配到作品。
- `no_result`：接口正常响应但没有候选作品。
- `endpoint_error`：超时、空响应、证书或解析错误。
- `ambiguous_match`：存在候选，但作者、题名或正文相似度不足。
- `not_attempted`：本次未执行自动查询。

新增 `lookup_note`，只记录接口和匹配过程，不承担年代判断。

### 系年状态

新增 `dating_status`：

- `exact`：可靠材料支持单一公历年份。
- `range`：可靠材料仅支持连续区间。
- `disputed`：不同研究给出互不一致的年份或区间。
- `activity_phase`：只能根据行迹确定较宽的创作阶段。
- `undated`：尚无可靠作品级系年。

保留 `date_start`、`date_end`、`date_label` 和 `date_precision`，但由 `dating_status` 约束：`undated` 时起止年份必须为空。

### 证据与复核

新增字段：

- `dating_method`：`chronological_edition`、`poet_chronology`、`event_anchor`、`itinerary_inference`、`activity_phase` 或 `unknown`。
- `source_type`：编年全集、诗人年谱、学术论文、古籍注本、历史数据库等。
- `manual_source_1`、`manual_source_2`：书目信息或稳定链接。
- `evidence_quote_or_summary`：简短证据摘要，不复制大段受版权保护文本。
- `review_status`：`auto_only`、`manual_single_source`、`manual_cross_checked`、`needs_review`。
- `research_note`：记录异说、题名问题和仍待解决的问题。

现有 `verification_status` 暂时保留为兼容字段，由新状态派生，不再作为唯一判断依据。

## 人工数据侧车

新增 `data/poem_dates_manual.csv`，以 `record_id` 为主键，只保存人工研究字段和人工年代覆盖值。生成脚本按以下顺序合并：

1. 读取诗歌语料并识别重复项与语料边界。
2. 执行或读取开放接口结果。
3. 读取人工侧车文件。
4. 以人工证据覆盖自动年代字段，但不覆盖自动查询日志。
5. 输出统一的 `data/poem_dates.csv`。

这样重新请求接口不会丢失人工考证，也能清楚区分机器检索与人工判断。

## 证据层级

按以下顺序采纳材料：

1. 学术整理的编年全集、作品系年笺注。
2. 可靠出版社出版的诗人年谱、行迹考。
3. 同行评审论文、学位论文中的单篇系年研究。
4. 正史、墓志、地方志、题序等一手历史锚点。
5. CBDB 等学术数据库提供的人物官职、地点和交游信息，仅用于限制区间。
6. 普通网页只作为发现线索，不能单独支撑最终年代。

若来源冲突，保留所有主要异说，`dating_status` 标为 `disputed`，并降低置信度。

## 首批核查顺序

首批 25 首按“已有编年材料的可能性”和“同一诗人可批量查证”排序：

1. 李白、王维、高适。
2. 王昌龄、李颀、李益。
3. 卢照邻、杨炯、骆宾王。
4. 李峤、马戴。

每首诗至少执行：题名异体检索、作者年谱检索、编年集检索、事件或行迹锚点检索。只有一个可靠来源时标记 `manual_single_source`；两个相互独立来源一致时才标记 `manual_cross_checked`。

## 错误处理

- HTTP 200 但正文为空或不是 JSON，记为 `endpoint_error`，不得写成“作品无系年”。
- 搜索正常但无候选，记为 `no_result`。
- 候选文本相似度不足，记为 `ambiguous_match` 并保留候选信息供人工复核。
- 人工来源只有模糊阶段时，只写区间或阶段，不生成虚假单年。
- 人工来源相互冲突时保留争议范围，不用平均值折中。
- 重复诗继承主记录的年代时，保留 `duplicate_of`，不计为新增独立系年成果。

## 测试与验收

测试先于实现，至少覆盖：

1. 接口解析失败会生成 `endpoint_error`。
2. 正常空结果会生成 `no_result`。
3. 匹配作品但没有年代会生成 `dating_status=undated`。
4. 人工侧车可覆盖年代但不会抹除自动查询状态。
5. `dating_status=undated` 的起止年份为空。
6. `exact` 的起止年份相同；`range` 和 `disputed` 的起止年份合法。
7. 100 条输出记录、重复关系和语料边界标记保持不变。

最终运行：

- `python3 -m unittest scripts/test_build_poem_dates.py`
- `python3 scripts/validate_project.py`
- `npm test`
- `git diff --check`

## 输出解释

最终覆盖率同时报告三组数字：记录级、去重后的唐代主体作品级、按精度分层的作品级。不得把重复记录继承的年代计作新发现，也不得把创作阶段范围与确切年份合并统计。
